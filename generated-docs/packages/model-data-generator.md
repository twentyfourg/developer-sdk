## Purpose

`model-data-generator` is an **interactive CLI tool** that reads [Sequelize](https://sequelize.org/) model files, infers data types and constraints, generates realistic fake data using [Faker.js](https://fakerjs.dev/), and optionally:

- **Bulk-inserts** the generated rows directly into a MySQL database, or
- **Writes** the data to a JSON fixture file under `./seeders/fixtures/`.

This accelerates development and testing by populating databases with realistic dummy data without writing seed scripts by hand.

## Usage

```bash
npx @twentyfourg-developer-sdk/model-data-generator
```

The tool will guide you through a series of prompts:

```
? Please confirm the path to the models folder:  ./src/db/models
? Filter for model names including: (optional)
? What model(s) would you like to populate?  (multiselect)

For each selected model:
  ? How many objects do you want to create for <model>?  1
  ? Run <model> as a dry run?  Yes / No
  ? Create a fixture file for <model>?  Yes / No
```

- **Dry run:** Data is printed to the console but **not** written to the database.
- **Fixture file:** A JSON file is written to `./seeders/fixtures/<tableName>.dummy.fixture.json`.

## Model File Convention

The generator expects model files to be named `*.model.js` and to export a **DTO** (Data Transfer Object) describing the Sequelize columns. The DTO key must follow the pattern `<tableName>DTO`.

```js
// Example: user.model.js
const { DataTypes } = require('sequelize');

module.exports.userDTO = {
  firstName: { type: DataTypes.STRING },
  lastName:  { type: DataTypes.STRING },
  email:     { type: DataTypes.STRING, unique: true },
  password:  { type: DataTypes.STRING },
  age:       { type: DataTypes.TINYINT, allowNull: true },
};
```

### Ignored Fields

Fields with the following keys are **skipped** during data generation:

- `primaryKey: true` — auto-generated by the database.
- `defaultValue: <any>` — already has a default assigned.

## Data Generation Strategy

Data is generated in **two passes**:

### 1. Match by Field Name (`randomByName`)

If a field name matches a well-known name (case-insensitive), a contextually appropriate value is generated:

| Field name | Generated value |
|---|---|
| `firstName` | `faker.name.firstName()` |
| `lastName` | `faker.name.lastName()` |
| `name`, `fullName` | `faker.name.findName()` |
| `email` | `test@24g.com` |
| `password` | bcrypt hash of `testpassword` (cost factor 10) |
| `message`, `description` | `faker.lorem.sentence()` |
| `timezone` | `faker.address.timeZone()` |
| `addressOne` | `faker.address.streetAddress()` |
| `city` | `faker.address.city()` |
| `state` | `faker.address.stateAbbr()` (2-char) |
| `country` | `faker.address.country()` |
| `zip` | `faker.address.zipCode('#####')` |
| `phone` | `faker.phone.phoneNumber('###-###-####')` |
| `*email*` *(contains)* | `<nanoid(5)>@24g.com` |
| `*link*` *(contains)* | `faker.internet.url()` |

### 2. Match by Sequelize Data Type (`randomByType`)

Any field that was not matched by name falls back to type-based generation:

| Sequelize type | Generated value | Range / notes |
|---|---|---|
| `STRING`, `CHAR` | `faker.datatype.string(length?)` | Respects `length` constraint |
| `TEXT` | `faker.lorem.sentences(n)` | `tiny`=2, default=3, `medium`=8, `long`=16 sentences |
| `BOOLEAN` | `0` or `1` | Random |
| `INTEGER` | Random integer | `-2,147,483,648` to `2,147,483,647` |
| `BIGINT` | `faker.datatype.bigInt()` | Full bigint range |
| `MEDIUMINT` | Random integer | `-8,388,608` to `8,388,608` |
| `SMALLINT` | Random integer | `-32,768` to `32,767` |
| `TINYINT` | Random integer | `-128` to `127` |
| `FLOAT`, `DOUBLE PRECISION`, `DECIMAL`, `REAL` | `faker.datatype.float()` | — |
| `NOW` | `faker.datatype.datetime()` | ISO datetime |

### Constraints

- **`unique`** — Values are pre-generated into a pool before insertion to guarantee uniqueness across all rows for that field.
- **`allowNull`** — When `true`, the generator randomly produces `null` for approximately half of the rows.

### Foreign Key References

When a field has a Sequelize `references` property **and** a database connection is available, the generator queries the referenced table for a random existing row and uses its value. This supports three reference formats:

```js
// String reference
references: 'users'

// Object reference with string model
references: { model: 'users', key: 'id' }

// Object reference with tableName
references: { model: { tableName: 'users' }, key: 'id' }
```

## Architecture

```
packages/model-data-generator/src/
├── index.js          # CLI entry point — prompts user and calls generate()
├── generate.js       # Orchestrates data generation and database insertion / file creation
├── randomByName.js   # Generates values based on field name heuristics
├── randomByType.js   # Generates values based on Sequelize DataType
├── references.js     # Resolves foreign key references via live DB queries
├── unique.js         # Pre-generates pools of unique values
└── util/
    ├── db.util.js    # mysql2 connection pool management
    └── randomEven.js # Returns a random boolean (50/50 coin flip)
```

### Module responsibilities

| Module | Responsibility |
|---|---|
| `index.js` | User prompts; collects `modelPath`, model selections, `howMany`, `dryRun`, `createFile` |
| `generate.js` | Loads model files, drives the per-row generation loop, inserts data or writes fixture files |
| `randomByName.js` | Name-based field matching (calls `randomByType` as a fallback) |
| `randomByType.js` | Type-based generation for any field with a `null` value after name matching |
| `references.js` | Resolves `references` FK fields from the live DB, then calls `randomByName` |
| `unique.js` | Pre-populates uniqueness pools for fields marked `unique: true` |
| `db.util.js` | Manages a singleton `mysql2` connection pool; reads host/credentials from env vars |

## Testing

Tests are written with [Jest](https://jestjs.io/) and live in `packages/model-data-generator/tests/`.

```bash
cd packages/model-data-generator
npm test
```

Jest is configured to run with verbose output and collect coverage.

### Test files

| File | What it tests |
|---|---|
| `dummyByName.spec.js` | Verifies that name-matched fields produce correctly formatted values (email format, alpha-only names, phone pattern, etc.) |
| `dummyByType.spec.js` | Verifies that type-matched fields produce values within the correct ranges and formats for all supported Sequelize types |
| `randomEven.spec.js` | Tests the 50/50 coin-flip utility |
| `references.spec.js` | Tests the foreign key reference resolution logic |
| `unique.spec.js` | Tests that unique value pools are generated without duplicates |
